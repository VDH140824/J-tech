2. Management Approach
To ensure the successful implementation and timely delivery of the project, the team adopts Scrum framework. This approach allows the team to be adaptive to changes, maintain continuous communication, and deliver incremental functionality through short iterations (Sprints). Project progress, tasks, and issues will be tracked transparently using tools such as GitHub Projects. Daily stand-ups, lanning, review, and retrospective meetings are conducted regularly to maintain alignment and continuous improvement. 
2.1 Project Process
The project applies the Scrum development process model, organized into 7 Sprints (2 weeks per Sprint) across a 14-week lifecycle:
Sprint 0 (Weeks 1 – 2): Project Initialization & Training
Finalize Software Requirements Specification (SRS) and architecture design.
Conduct team training on Spring Boot, React, and Git workflows.
Initialize project repositories, CI/CD pipelines, and base database schemas.
Sprint 1 (Weeks 3 – 4): Core Authentication & Lesson CMS
Implement User/Admin Authentication & Authorization (Spring Security + JWT).
Build Admin Dashboard for Lesson CMS and video upload modules.
Sprint 2 (Weeks 5 – 6): Dekiru Curriculum & Media Streaming
Develop Student Lesson View, Kanji stroke canvas (HanziWriter), and Grammar detail screens.
Implement video streaming and interactive transcript/audio player.
Sprint 3 (Weeks 7 – 8): AI Integration (Speech & Pronunciation Assistance)
Integrate Whisper STT and Gemini Flash API.
Implement voice recording and AI-driven pronunciation error analysis & feedback (non-grading).
Sprint 4 (Weeks 9 – 10): Gamification & Mini-games
Develop Kanji Battle (radical matching) and Grammar Quest mini-games.
Implement Streak system, EXP progression, and real-time Leaderboards.
Sprint 5 (Weeks 11 – 12): System Integration & Performance Optimization
End-to-end integration testing between Spring Boot, React, and Gemini AI.
Caching implementation (Redis) and database query optimization.
Comprehensive defect fixing and UI/UX polishing.
Sprint 6 (Weeks 13 – 14): Final Deployment, Acceptance Testing
Conduct User Acceptance Testing (UAT) and Security/Load testing.
Finalize all technical documentation, user guides, and slide presentations for defense.
2.2 Quality Management
To achieve high quality and meet the software requirements, the team applies the following quality assurance strategies:
Defect Prevention:
Define clear Definition of Done (DoD) and Definition of Ready (DoR) for all tasks.
Establish consistent coding conventions, project architecture rules, and static code analysis (e.g., using SonarQube).
Reviewing:
Code Review: Every feature branch must be reviewed and approved via Pull Requests by at least one peer/lead before merging into the main branch.
Design & Documentation Review: Review database schemas, API contracts (OpenAPI), and UI/UX wireframes before actual implementation.
Unit Testing:
Developers are responsible for writing automated unit tests (e.g., JUnit, Mockito for Spring Boot; Jest for frontend) covering core business logic and critical utility functions, aiming for at least 86% code coverage.
Integration Testing:
Verify the interaction between different layers (Controller - Service - Repository) and test end-to-end API communication using tools like Postman or Spring Boot Test.
System Testing:
QA/Testers perform functional, UI, and scenario-based testing on a staging environment to ensure the whole system satisfies all functional and non-functional requirements prior to release.

Google Drive
Google Docs
Google Sheets
GitHub
The team uses Google Drive to store and manage project documents such as the Project Introduction, SRS, design documents, testing documents, reports, and presentation slides.
Google Docs and Google Sheets are used for collaborative editing and updating project information. GitHub is also used to store and manage technical documents related to the project, helping the team track changes and maintain document versions.
The Project Manager is responsible for monitoring progress, consolidating documents, and reviewing the final versions before submission to the mentor.
6.2 Source Code Management
Management Tools:
GitHub
The team uses GitHub to manage and store the project source code, including the Front-end, Back-end, API, Database, and AI integration components.
Each team member works on a separate branch corresponding to their assigned tasks, then commits and pushes the code to the repository. Once a feature is completed, the code is reviewed and merged into the main branch to ensure system stability.
The Project Manager is responsible for monitoring the repository, managing source code integration, and preparing a stable version for testing, deployment, and demonstration.
